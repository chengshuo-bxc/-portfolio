多店铺价格监控与分级告警

多店铺运营里，"价格被卖低"往往等到财务对账才发现，损失已经发生。本系统定时盯住正在参加活动、还没结束的商品，把「单件预估实收 / 活动报名价」和货盘底线逐款比对，破了线立即分级告警：轻的群里通知、重的自动加急 + 未读催办，并盯到有人处理为止。平时很安静 —— 没破价不打扰，同一条只报一次。

签名池批量取数 分级告警 · 已读闭环 多店一店一浏览器 网页控制台

项目背景

多家店铺同时在做活动，价格口径复杂（有的款要控价、有的款只看成本）。人工每小时翻后台比对不现实，破价又必须尽快发现。

核心难点

后台接口签名一份只能用一次（第 2 次即失败，且伪装成"请求频繁"）；货盘表在在线文档里、控价列按日期分组会往右长；告警还要能做到分级 + 不重复打扰 + 已读闭环。

signature pool

先解决"取数"：签名池打法

[逆向要点] 单个签名寿命极短，但页面一次加载会产生上百份签名。所以一次性全薅下来存池，一个请求花一份、失败换一份重试——全程纯接口翻页，完全不用点页面，几百个商品几页翻完。

core/pdd_client.py · 签名池 
def post(page, sig, path, payload, refill_url):
    for _ in range(5):
        ac = sig.take()                       # 取没用过的一份签名
        if ac is None:
            sig.refill(page, refill_url); ac = sig.take()   # 池空 → 刷新页面补货
        j = page.request.post(BASE + path, data=json.dumps(payload),
                              headers={"anti-content": ac, ...}).json()
        if j.get("success"): return j          # 成功
        time.sleep(0.4)                        # 失败 → 换一份再来
    raise RuntimeError("连续失败")
caliber

口径：控价款 vs 不控价款，逐款比底线

控价款

底线 = 货盘里「拼多多,唯品会」控价列。实收、报名价两个都判，严格小于才算破（等于不算）。

不控价款

底线 = 成本价（防亏本卖）。货盘的控价列按列名定位、逐款取最近一次非空 —— 绝不硬编码列号（列会往右长）。

core/rule.py · 判定 + 分档 
base = item["成本价"] if item["不控价"] else item["底价"]     # 底线按款性质取
if 价 < base - tol:                                          # 严格小于才算破
    margin = (base - 价) / base

def level_of(margin, mid=20, high=40):                       # 按幅度分档
    return "高级" if margin >= high else "中级" if margin >= mid else "群通知"
alerting

分级告警 + 已读闭环（本项目的重点）

任何破价都发群通知 + 完整清单；严重的额外催办，并盯到有人读了才停。

$ 幅度 < 20% → 只发群通知（含清单，不打扰）
[+] 幅度 ≥ 20% → 加急；未读 → 短信
[+] 幅度 ≥ 40% → 加急；未读 → 电话
$ 每 10 分钟查一次「已读」，读了立刻闭环；价格回线也算结束
