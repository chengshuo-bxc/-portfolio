电商商品价格与评论自动化监控 RPA

对标简历「电商平台商品价格与评论自动化监控」项目（原为 UiPath+Python 混合）。本复现用 Python + DrissionPage：京东竞品价格定时采集，价格变动超阈值自动告警，波动报表出图。登录态会话复用全链路打通。

会话登录态复用 阈值告警实测触发 价格波动报表 DrissionPage

项目背景

运营团队要实时掌握竞品价格动态。人工每天刷网页太低效。目标：定时采集竞品价格，自动比对历史，波动超阈值就通知人，并生成价格走势报表。

核心难点

京东未登录访问商品页会 302 跳登录页；新版商品页价格不是写死在源码，而是 JS 渲染（旧选择器 #jd-price 只剩在 CSS 里）；登录 cookie 名单随版本变化（pt_key/pt_pin 是老体系，新版是 pin/unick/token）。

login reuse

会话登录态复用（对应简历第 3 条）

三级登录态策略：[逆向要点] 浏览器持久会话最稳 → cookies 文件兜底 → 都失效才引导扫码。首次扫码一次，之后长期复用，跳过验证码。

core/fetcher.py · LoginManager 
# 1) 优先复用浏览器持久会话（DrissionPage 固定用户目录，登录一次长期有效）
if self._check_ok():
    self._save_cookies()          # 同步最新 cookies 到本地文件
    return session

# 2) 复用本地 cookies 文件（注入浏览器后再验证）
if os.path.exists(COOKIE_FILE) and any(
        c['name'] in LOGIN_COOKIE_NAMES for c in cookies):
    self.inject_to_browser()
    if self._check_ok():
        return session

# 3) 都失效 → 引导扫码一次，之后长期复用
self.page.get('https://www.jd.com')
for i in range(120):              # 轮询等登录标志 cookie 出现
    if self._has_login_cookie(): break
    time.sleep(3)
self._save_cookies()
core/fetcher.py · 登录标志 cookie 名单 
# [逆向要点] 京东登录 cookie 分新旧体系, 全要覆盖:
# 新版: pin / unick / sdtoken / token   扫码: pt_key/pt_pin   密码: pwdt_id
LOGIN_COOKIE_NAMES = ('pt_key','pt_pin','pwdt_id','pin','unick','sdtoken','token')

def _check_ok(self):            # 访问商品页, 不再 302 到 passport 才算登录有效
    self.page.get(config.COMPETITORS[0]['url'])
    self.page.wait(2)
    return 'passport.jd.com' not in self.page.url
price selector

新版商品页价格选择器（被坑实录）

先照老教程用 #jd-price，结果抓空——它在 DOM 里只剩 CSS 类名。页面 dump 后定位到新版结构：价格在 .product-price--value，JS 渲染需轮询等出现。

core/fetcher.py · 价格采集 
# 价格是 JS 渲染的, 轮询等它出现 (对应 RPA"等待元素出现")
for _ in range(config.LOAD_TIMEOUT * 2):
    price_ele = page.ele('.product-price--value', timeout=1)  # 新版页面价格
    if price_ele and price_ele.text.strip(): break
    time.sleep(0.5)
price = float(price_ele.text.strip().replace(',', ''))

# 库存: 无货时页面出现"暂时售完", 有货显示"加入购物车"
stock = '无货' if '暂时售完' in body_text[:2000] else '有货'
